# Submitting Ember to Flathub

The application ID is `dev.darkpyonix.Ember`. The owner controls the domain `darkpyonix.dev`
and serves its verification file from a Cloudflare Worker.

Everything Flathub reviews is generated by `tools/packager-linux/flatpak.sh`.
`flathub/ember.sh` drives it for one Ember release. The `Linux packaging` workflow
generates and lints the submission on every run and uploads it as the
`flathub-submission-ember` artifact. Ember has no release yet, so two of the workflow's
inputs are stand-ins: the archives are the published calculator samples, and the
screenshot is Ember's large icon. Everything else is what will be submitted.

**The submission is on hold.** Nothing here opens a pull request.

## 1. Before the pull request (owner)

- [x] Application ID: `dev.darkpyonix.Ember`.
- [ ] Domain verification. Once the app is accepted, flathub.org (Developer settings,
      Verification) issues a token for
      `https://darkpyonix.dev/.well-known/org.flathub.VerifiedApps.txt`; the Worker
      serves it.
- [ ] Publish an Ember release on `DarkPyonix/darkpyonix-ember` with one archive per
      architecture. Each archive holds a top directory with the `ember` executable and the
      renderer in `lib/` beside it. Default asset names: `ember-linux-x64.tar.gz` and
      `ember-linux-arm64.tar.gz`.
- [ ] Commit a screenshot to the Ember repository and tag the release. The listing points at
      it through raw.githubusercontent.com pinned to that tag; the packager refuses a URL
      that follows a branch.
- [ ] Rewrite the summary and description in `flathub/dev.darkpyonix.Ember.toml` if the
      repository's one-line description is not what the store page should say. Move the file
      into the Ember repository as its `Dioxus.toml` when Ember gets one.
- [ ] Release notes for the version (`[linux.store] release_notes`).

## 2. Generate the submission

```sh
cargo build --release -p packager-linux
PACKAGER_LINUX=target/release/packager-linux tools/packager-linux/flathub/ember.sh \
    --tag v1.0.0 --version 1.0.0 \
    --screenshot docs/screenshot.png --screenshot-caption "The console" \
    --out flathub-ember --build repo --lint
```

The script downloads the release archives to compute their SHA-256, takes the icons from
`src-tauri/icons/` at the tag (or `--icon`), and writes into `flathub-ember/` the files of
the `flathub/dev.darkpyonix.Ember` repository: `dev.darkpyonix.Ember.json`, the desktop
entry, the metainfo and `icons/`.

## 3. Check before opening the pull request

- [ ] `lint-manifest.json` and `lint-repo.json` show no errors other than the ones only
      Flathub can clear (the domain not yet verified).
- [ ] `flatpak run dev.darkpyonix.Ember` opens the window. The workflow's calculator step
      shows how to do that under a virtual display.
- [ ] `appstreamcli validate --no-net flathub-ember/dev.darkpyonix.Ember.metainfo.xml` passes.
- [ ] The runtime branch (default 26.08) is the newest one Flathub offers.

## 4. Pull request (when the hold is lifted)

Fork `flathub/flathub`, branch from `new-pr`, add the files from `flathub-ember/` at the
repository root, and open the pull request against `new-pr` titled
`Add dev.darkpyonix.Ember`. After it is merged, every later release is a commit in
`flathub/dev.darkpyonix.Ember` that changes the archive URLs and their digests: run
`ember.sh` again with the new tag.
